# Security policy

## Supported versions

MicLine is in development and has no supported public release yet. Security
fixes target the latest `main` revision; older development builds receive no
backports. Do not treat development signing as distribution approval.

## Report a vulnerability privately

Use GitHub's [Report a vulnerability](https://github.com/thesammykins/micline/security/advisories/new)
form. GitHub private vulnerability reporting is the only accepted security-report
channel. Do not file a public issue, discussion, or pull request containing a
vulnerability or sensitive data.

Private vulnerability reporting must be enabled and checked before public
availability. While this repository remains private, GitHub may not offer that
form. If it is unavailable, do not disclose the report through a public fallback;
reporting readiness is blocked until the private form is available.

Include affected revision/version, reproduction steps, impact, and a minimal
example without credentials, audio recordings, plugin state, or personal paths.
Do not test against other people's devices or accounts. Review diagnostic exports
before attaching them: allowlisted reports can still identify a hardware setup.

The maintainer reviews reports through GitHub. No response-time guarantee is
currently offered. Keep details private while remediation is discussed.
